Scope: everything except `node/desktop.mjs`, `src/agent/computer-agent.mjs` and the voice files, which other

## Fixed

**Image reply vanished** (7b375a9). The brain returned only its last model step's text. So what she wrote alongside
`image_create` was streamed to the screen, then replaced when the reply with the picture arrived, and never saved. If
she said nothing after the tool, the provider treated the empty answer as a failure, the turn errored, and the picture
was dropped. Fixes:
- The reply now joins every step's text.
- An empty answer or an outage after something was already shown keeps what was shown.
- `chat.message` events carry message ids, so a picture that lands mid-reply is loaded afterwards.
- Leaving the Chat view mid-reply no longer cancels the turn.

**Crashes.** The process exited (unhandled exception or rejection) on:
- a malformed request line (`GET //[`)
- a `null` JSON body on the public sign-in routes
- a fetched page redirecting to an invalid `Location`
- a client reset during an egress-proxy CONNECT

**Outreach:**
- One queued email could be sent twice when two flushes overlapped.
- Re-saving a lead that had replied or been lost made it sendable again.
- "No thanks / Regards" and HTML-escaped snippets were not recognised as opt-outs.
- The opt-out footer was dropped when the body merely mentioned "opt out".
- Do-not-contact had gaps: display names, subdomains, `reply` with an explicit `to`, and drafts.
- Personal-inbox sends entered the outreach sequence and broke its thread replies.
- The bounce breaker's pause was lost behind a 24-hour pause.
- Follow-ups could go out after the 4-email sequence had finished.

**Approval gates:**
- `reminder_update` (needs no approval) could reschedule or make recurring an approved scheduled agent task.
- `schedule_task` and task-queuing `rule_create` were "routine" instead of "consequential".
- An expired or revoked `high` grant fell to `autonomous` instead of the previous level, which for
  spending, messaging and deletion is more permissive than the default.

**Watches and rules:**
- Overlapping ticks fired one-shot watches twice.
- An email watch created on an empty inbox swallowed the first match as its baseline.
- A cancelled or interrupted laptop check stopped the watch for good.
- `watch_cancel('%')` cancelled every watch.
- Prefix rule triggers got around the loop guards.

**Smaller fixes:**
- To-do dedupe merged "assignment 2" with "assignment 3".
- A research ingest was lost to one bad claim.
- `questions.wait()` on an aborted signal hung for 6 hours.
- The briefing's mood was never wired.
- Request bodies, DSH output and Hermes SSE corrupted split UTF-8 characters, and Hermes ignored CRLF frames.
- Web fetches had no overall deadline.
- `append_pdf` could read any PDF on the server through a caller-supplied `path`.
- A failed Google reconnect deleted the working token.
- Unbounded Google sign-in states.
- The pet pages read the token from the wrong key.
- The ESP32 `secrets.h` was not git-ignored.
- `deploy-server.sh` hid build failures.
- `pr-merge.sh` deleted the branch even when the merge was refused.

## Not changed: needs a decision or more than a contained fix

Security and auth:
- **TOTP lockout DoS.** The 5-strikes lockout is global, and anyone on the internet can trigger it through
  `/v1/auth/login` with the owner's email and bad codes. The owner's email is also revealed by `/v1/auth/signup`,
  which returns 409 for it. Needs per-source counters.
- **Prompt injection reaches tools that need no approval.** `task_create` and `code_task` (networked agent, and the
  GitHub MCP when `GITHUB_TOKEN` is set), `profile_set` and `answer_task_question` are all `safe`. Text in a fetched
  page or an email can trigger them. Gating them is a product decision about how many approvals you want.
- **Google sign-in can join someone else's account.** Password signup never verifies the email, and `fromGoogle`
  returns whatever account already has that address. Someone who pre-registers your email and gets approved shares
  your account when you later sign in with Google.
- **Members can claim unattached files.** A member can attach any file that isn't yet in a conversation (owner
  uploads included) if they know its id. Needs an `uploaded_by` column.
- **No member upload quota.** Unclaimed uploads are never cleaned up.
- **Backups contain secrets.** The default (non-secrets) backup's `friday.sqlite` holds the TOTP seed and the
  password, session and device-token hashes.
- **Deployer:**
  - A redeploy deletes the old container before the new one starts.
  - A symlinked project folder is followed.
  - The `friday_apps` network is not internal, so a deployed app bypasses the egress proxy.
  - Docker log frames come back garbled.
- **`/v1/events` refuses connections early.** It returns 503 well below its limit because the cap counts internal bus
  subscribers, and every owner-token client shares a cap of 4.
- **`node/reel-edit.mjs` reads outside its folder.** It allows `Read`/`Glob`/`Grep` without a path scope, so a
  steered brief could read files outside `Downloads/friday-media`. This needs checking against Claude Code's rule
  semantics.

Correctness:
- **dm-chat `replyNow` can double-send.** It runs after a 20 s wait even while the tick is still sending, so a friend
  can get two replies.
- **Out-of-office replies are reprocessed.** With two OOO replies in a week, each tick reprocesses them, pushing
  `next_at` out and calling JEV again.
- **A Gmail timeout can resend an email.** When `send` times out, Google may already have sent it, and the row is
  retried 30 min later.
- **Prospector bugs, not fixed here.** `#running` can stay stuck, and a malformed `mailto:` throws.
  `src/prospector.mjs` is being rewritten on `wip/prospect`, so I left it alone.
- **Wrong timezone.** Mood uses the server clock instead of your timezone, and a rule-triggered briefing ignores your
  timezone.
- **Rule fires the global cap blocks still use up the rule's cooldown.**
- **Small things that grow without limit.** `followup:<task>` settings rows, and the dm-chat `#fails` map.
- **Without `/proc/meminfo` the governor thinks memory is exhausted** and blocks all work. This only matters if Friday
  runs somewhere other than Linux.
- **Smaller agent bugs:**
  - The embedding call on each turn can't be cancelled and can hang for 120 s.
  - Tool-group stickiness is counted across all conversations, not per conversation.
  - A team sub-task that throws leaves its siblings running.
  - The agent-runner concurrency cap can be exceeded.
- **Smaller web and node bugs:**
  - The ESP32 POSTs on the same TLS client as its SSE stream, and it uses `setInsecure()`.
  - `bin/friday` trusts a stale pidfile.
  - `browser.mjs` adds two download handlers to popup tabs.
  - The `friday-node` localhost check is a loose regex. Not fixed: `wip/desktop` is editing that file.
  - Settings `build()` has no guard against overlapping calls.
  - Inline `style` attributes are blocked by the CSP.
  - `#login_error=` shows text from the link.
  - A `#pair=` link replaces a working token before it is verified.
  - `deploy-server.sh` builds the data path from the SSH target string.
